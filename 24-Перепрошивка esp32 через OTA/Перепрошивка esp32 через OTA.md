## [Перепрошивка ESP32 через OTA](#) 

> OTA-обновление (от англ. Over-The-Air update, «обновление по воздуху») - способ обновления встроенных систем, при котором обновления передаются через беспроводные сети. Это позволяет распространять новые версии программного обеспечения, снижать затраты на их доставку и ускорять внедрение

Для реализации обновления прошивки ESP32 через OTA необходимо: 

- настроить веб-сервер, который обслуживает файл обновления встроенного ПО;

- настроить ESP32 для подключения к этому серверу и загрузки файла обновления;

- использовать библиотеку для выполнения обновления, например ArduinoOTA;

- добавить код, поддерживающий беспроводную загрузку, в прошивку и загрузить его на микроконтроллер через проводное USB-соединение. Этот код позволяет в будущем подключаться и загружать код по Wi-Fi;

- убедиться, что в обновлённой прошивке остаётся код, поддерживающий OTA, иначе беспроводные обновления не будут возможны в следующий раз. 

Алгоритм процесса обновления прошивки через OTA: 

- устройство загружает новую прошивку порциями и сохраняет её в отдельной области памяти («пространство OTA»);
- как только вся прошивка будет загружена и проверена, загрузчик устройства начнёт действовать. Он переместит новый код из пространства OTA в пространство приложения, а затем передаст управление коду в пространстве приложения.
 
Важно: во время обновления лучше отключить любые подключённые устройства, если они выполняют критичные задачи. По возможности обновлять устройство через защищённое соединение (HTTPS), особенно если обновление выполняется через интернет. 

Пример кода для настройки OTA-обновлений на ESP32 с использованием библиотеки ArduinoOTA: 

- включить библиотеки ArduinoOTA и WiFi в верхнюю часть скетча: 

```
#include <ArduinoOTA.h> 
#include <WiFi.h>
```

- настроить соединение Wi-Fi: вызвать функцию WiFi.begin() и передать имя и пароль сети Wi-Fi;

- инициализировать библиотеку ArduinoOTA: вызвать функцию ArduinoOTA.begin();

- установить имя хоста и пароль для OTA-обновления с помощью функций ArduinoOTA.setHostname() и ArduinoOTA.setPassword();

- настроить функцию для обработки входящих запросов на обновление OTA с помощью функции ArduinoOTA.onStart();

- настроить функцию для обработки хода обновления OTA с помощью функции ArduinoOTA.onProgress();

- настроить функцию для обработки завершения OTA-обновления с помощью функции ArduinoOTA.onEnd();

- вызвать функцию ArduinoOTA.handle() в основном цикле программы, чтобы прослушивать и обрабатывать запросы на обновление OTA.

#### Руководство по интеграции

Интегрировать ElegantOTA в существующий код довольно просто. В этом руководстве предполагается, что у вас уже есть простой код веб-сервера и вам нужно лишь добавить в существующий код следующие строки:

- Включить зависимость. В самом начале скетча подключите библиотеку ElegantOTA.

```
#include <ElegantOTA.h> 
```

- Добавить begin функцию. Теперь добавьте begin функцию ElegantOTA в блок настройки вашего скетча. Это позволит внедрить маршруты и логику ElegantOTA в веб-сервер.

```
ElegantOTA.begin(&server);
```

- Добавить loop функцию. Последняя часть — вызов loop функции ElegantOTA в блоке цикла вашего скетча. Этот блок цикла необходим для того, чтобы ElegantOTA обрабатывала перезагрузку после OTA-обновления.

```
ElegantOTA.loop(); 
```

- Итоговый код. Вот и всё! Так будет выглядеть готовый к использованию пример. После загрузки кода на вашу платформу вы сможете получить доступ к порталу ElegantOTA на:

```
 http://<YOUR_DEVICE_IP>/update 
 ```
 
```
/*
  -----------------------
  ElegantOTA - Demo Example
  -----------------------
  Skill Level: Beginner
 
  В примере представлено простое приложение с элегантной функциональностью OTA.
 
  Github: https://github.com/ayushsharma82/ElegantOTA
  WiKi:   https://docs.elegantota.pro
 
  Works with both ESP8266 & ESP32
  -------------------------------
  Upgrade to ElegantOTA Pro: https://elegantota.pro
*/
 
#if defined(ESP8266)
  #include <ESP8266WiFi.h>
  #include <WiFiClient.h>
  #include <ESP8266WebServer.h>
#elif defined(ESP32)
  #include <WiFi.h>
  #include <WiFiClient.h>
  #include <WebServer.h>
#endif
 
#include <ElegantOTA.h>
 
const char* ssid = "........";
const char* password = "........";
 
#if defined(ESP8266)
  ESP8266WebServer server(80);
#elif defined(ESP32)
  WebServer server(80);
#endif
 
void setup(void) 
{
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, password);
  Serial.println("");
 
  // Wait for connection
  while (WiFi.status() != WL_CONNECTED)
  {
    delay(500); 
    Serial.print(".");
  }
  Serial.println("");
  Serial.print("Connected to ");
  Serial.println(ssid);
  Serial.print("IP address: ");
  Serial.println(WiFi.localIP());
 
  server.on("/", []() 
  {
    server.send(200, "text/plain", "Hi! This is ElegantOTA Demo.");
  });
 
  ElegantOTA.begin(&server);    // Start ElegantOTA
  server.begin();
  Serial.println("HTTP server started");
}
 
void loop(void) 
{
  server.handleClient();
  ElegantOTA.loop();
}
```

#### Примеры

В репозитории ElegantOTA есть два примера настройки: Demo и Async Demo. Эти примеры показывают, как интегрировать OTA (Over-the-Air) обновления в ваш проект с использованием различных типов веб-серверов, что позволяет выбрать оптимальный вариант для ваших конкретных нужд.

#### Демо

Демоверсия предназначена для тех, кто использует встроенный веб-сервер своей платформы. Она должна работать без каких-либо зависимостей.

#### Демонстрация асинхронного режима

В демонстрационном примере асинхронного режима используется AsyncWebServer, который значительно повышает производительность. Используйте этот пример только в качестве справочного, если в вашем проекте используется AsyncWebServer. Подробнее об этом читайте в документации по «асинхронному режиму».

#### Асинхронный режим

ElegantOTA включает функцию асинхронного режима, которая позволяет использовать асинхронный веб-сервер для управления OTA-обновлениями. При включенном асинхронном режиме ElegantOTA использует ESPAsyncWebServer для обработки всех HTTP-маршрутов.

Этот режим следует включать только в том случае, если вы используете библиотеку ESPAsyncWebServer в своем проекте/прошивке. Вы не можете одновременно использовать синхронные WebServer и ESPAsyncWebServer библиотеки в одной прошивке.

#### Рекомендуемые зависимости

Установите зависимости в зависимости от вашей платформы:

```
ESP8266:
---------------------------------------
(ESP32Async) ESPAsyncTCP - v2.0.0
(ESP32Async) ESPAsyncWebServer - v3.7.3

ESP32:
---------------------------------------
(ESP32Async) AsyncTCP @ v3.3.7
(ESP32Async) ESPAsyncWebServer - v3.7.3
```

#### Использование нерекомендуемых зависимостей (экспериментально)

Если ваш проект напрямую зависит от форка зависимости, не указанного выше, вам необходимо выполнить следующие действия если вы используете PlatformIO:

Пожалуйста, убедитесь, что вы установили ElegantOTA «вручную», следуя инструкциям в руководстве по установке

Откройте library.json файл в папке библиотеки ElegantOTA и удалите dependencies параметр. Это отключит автоматическую установку рекомендуемых зависимостей.

#### Включение асинхронного режима

Пожалуйста, выполните действия в соответствии с вашей платформой:

При использовании Arduino IDE вам придется включить асинхронный режим, отредактировав строку в библиотеке ElegantOTA, поскольку в Arduino IDE пока нет возможности задавать флаги сборки:

- Перейдите в каталог библиотек Arduino

- Откройте папку ***ElegantOTA***, а затем папку ***src***

- Найдите макрос ELEGANTOTA_USE_ASYNC_WEBSERVER в файле ElegantOTA.h и установите для него значение 1:

```
#define ELEGANTOTA_USE_ASYNC_WEBSERVER 1
```

Сохраните изменения в файле ElegantOTA.h.

Теперь вы готовы использовать ElegantOTA в асинхронном режиме для OTA-обновлений с помощью библиотеки ESPAsyncWebServer.

#### Преимущества асинхронного режима

Включение асинхронного режима для ElegantOTA дает несколько преимуществ:

- Неблокирующая работа: в асинхронном режиме ElegantOTA использует возможности асинхронного веб-сервера ESPAsyncWebServer. Это означает, что OTA-обновления не будут блокировать основной цикл вашего устройства. Это позволяет вашему устройству продолжать выполнять другие задачи, пока в фоновом режиме устанавливаются OTA-обновления.

- Улучшенная отзывчивость: ваше устройство может реагировать на действия пользователя или другие процессы во время OTA-обновлений, обеспечивая более комфортную работу.
